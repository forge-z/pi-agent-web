# Provider connections and compact sidebar

The sidebar keeps conversation creation, search, active/deleted history, Tasks, Settings and the profile/logout controls. Conversation history fills the remaining height. The former continuity note is removed; palette, appearance and the ChatGPT connection controls now live in Settings. Login-page appearance controls remain available before authentication.

Settings groups provider connections, new-conversation defaults, browser appearance/language and MCP servers. OpenAI offers ChatGPT OAuth or an OpenAI API key. Anthropic offers a standard API key from Anthropic Console; DeepSeek offers its standard API key using the native provider catalog. API-key status means a key is configured; saving it does not verify access by making a paid model request. OAuth remains the existing provider-owned flow. Claude subscription/CLI integration is outside this feature.

Keys use write-only password inputs with autocomplete, capitalization and spell checking disabled. They are sent only in the authenticated API request body, never saved in browser storage or echoed into the UI. Inputs clear before the save request completes and on dialog close, logout/reset, or authentication-method change. Known credential metadata selects the current method without changing it. Any replacement requires an explicit checkbox; the OpenAI text identifies the existing connection/key and the requested replacement. Connection failures show generic Portuguese/English messages. Closing/logging out during a pending save prevents stale UI feedback.

Model forms select provider, model and reasoning effort. Defaults and per-conversation settings send the chosen provider explicitly. Each form uses that provider's catalog; a conversation's existing provider takes precedence over the global default, including when model IDs overlap. After credential changes, open default-model choices refresh from the new catalog without saving a new default automatically.

## Validation

Frontend tests exercise read-only metadata loading, required replacement acknowledgment, OpenAI API/OAuth transitions, DeepSeek save/replacement and model selection, immediate key clearing during pending requests, sanitized errors in English, clearing on method/close/logout, avoiding stale updates after logout, preserving a key draft across language changes, and provider-specific conversation catalogs. OAuth completion/cancellation also restores enabled controls without reopening Settings. Existing theme, language, conversation-menu, composer and task-delivery tests cover the moved controls and related behavior. Browser evidence and final integrated checks are coordinated by the parent agent using local mocked providers; no real account or paid request is needed.
